# App audit — 27 October 2026

Reviewed payment, invoice, stock and challan saving; browser recovery; financial calculations; dialogs; dependency advisories; and deployment configuration. Tests use generated sample records and simulated Sheets/Drive, never the live shop ledger.

## Fixes

- **Challan deletion recovery:** the durable queue now accepts `deleteChallanPhotos` after reload. Previously a valid saved deletion was incorrectly treated as corrupt storage.
- **Mobile invoice layout:** ordinary invoices now participate in the original flex layout through the shared challan wrapper. This restores the anchored footer and scrolling item area.
- **Rejected invoice edits:** retry and discard controls are available inside the invoice viewer, where a failed background edit is visible. Discard reloads the confirmed invoice without overwriting another device’s edit.
- **Overlapping dialogs:** a shared, reference-counted scroll lock restores the original page scrolling only after the last dialog closes.
- **Malformed stock queues:** structural validation rejects missing movement arrays, null entries, unsupported actions, duplicate operation IDs and invalid quantities before projecting pending changes. Original storage is preserved.
- **Recovery exports:** include pending stock requests and raw challan queue data, including malformed entries. An inaccessible photo store no longer prevents exporting the other saved requests.
- **Browser compatibility:** shared UUID generation uses secure random bytes when `randomUUID` is unavailable. Plain-HTTP challan saving explains the HTTPS/localhost requirement; cross-tab locking remains enforced.
- **Security:** removed a debug access token and endpoint from local task notes before committing; ignored local cloud/agent credential directories. Updated Vite to 7.3.7 and source-map-js to 1.2.2. The post-update npm audit reports zero known advisories.

## Performance and maintenance

- Refresh challans after photo batches rather than each uploaded page. A ten-page batch needs two worker refreshes instead of eleven, excluding initial setup/user refreshes.
- Index invoices and photos by challan ID when listing/reconciling them, replacing repeated full-array searches.
- Share the Drive deletion routine between scheduled cleanup and manual deletion, preserving interrupted-operation recovery.
- Keep separate frontend/backend validation, integer paise, exact measurement arithmetic, revision checks and durable queues. Reducing line count alone is not a useful reason to remove these protections.

## Deployment and limits

Deploy the bundled Apps Script **1.30.4** as a new version of the existing deployment. Run `setup()` and `setupChallanStorage()` if this Sheet has not yet enabled challan storage; existing configured storage needs no new columns for these audit fixes.

Real Google consent, private Drive access, scheduled cleanup execution and physical phone camera behavior still need the Sheet owner’s deployment. Local tests simulate these services. Web Locks require HTTPS or localhost. Private browser storage must remain open until pending uploads finish.

The production entry bundle remains about 340 KB gzipped and emits Vite’s existing size warning. This audit reduces repeated work without introducing new runtime dependencies or speculative caching of financial data.
